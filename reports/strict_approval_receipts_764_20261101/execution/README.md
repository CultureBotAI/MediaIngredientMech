# Strict approval receipt execution evidence

This package records Step 6 implementation and execution against durable merged base `7a06935dceb6ffc4ccccc1a1693e01f2950a8601`. It does not grant scientific approval. The selected final execution receipts record completed local checks. Native structured review, committed-head review and remote CI remain separate assessments of their actual later state.

The change implements the strict receipt and checkpoint portions of #764/#766/#765 while retaining #817's exact-byte approval contract. It does not introduce `supersedes_content` or section-equivalence exceptions. The receipt helper validates complete operations and true integer positions, preserves the real native assertion/edge identity formulas, verifies the historical prefix even if receipt files have been deleted, and binds the frozen hold checkpoint before replaying its suffix. A changed frozen-owner byte history after that checkpoint is rejected even if a later receipt restores the earlier hash (#1065). Consumers independently recompute one verified chain per invocation, preserve separate plan pins, and reject duplicate indexed claims (#1066).

`selection.final.json` identifies every archived original by its absolute historical path and SHA-256, including multiple versions of one path. Those names are provenance, not a requirement that the original checkout still exists. `payloads.tar.gz` deduplicates payload bytes by SHA-256; `manifest.json` binds the package files. The verifier checks byte identity, command/log links, the selected README, and explicit durable Git blobs. It does not recursively certify every path mentioned by an archived report or establish scientific correctness.

Unchanged source and before-state products are resolved from the declared durable base's regular Git blobs, not from current YAML or a feature commit. The repository must contain that public base object. A shallow checkout lacking it must fetch it explicitly before verification; the verifier performs no network access and fails clearly when it is unavailable. Historical verification remains valid after later owner edits; optional `--current-scope` checks whether the separately declared current paths still match this execution. `--require-tracked` additionally checks package bytes against the current committed tree. Neither option substitutes current files for historical evidence.

The package deliberately omits copied temporary repositories, generated test corpora, caches and bulky full/supported KGX payloads. Exact excluded product identities and hashes are recorded where known, alongside native manifests and command evidence. Rebuilding those products requires the native dependencies and commands recorded in the execution context; this compact archive does not claim complete offline KGX replay. Source snapshots and probe code retained from the authors/reviewer allow bounded controls to be reconstructed, but original path-dependent fixtures may need to be recreated. The immutable prior evidence indexes retain their original inventories without implying that every disposable member is shipped here.
