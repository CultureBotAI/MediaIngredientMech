# Independent contract requirements for the four-event publisher extension

The sealed design is supported as a direction, with the following concrete requirements carried into its closed implementation contract. These are implementation obligations identified before code exists, not newly reproduced defects in a nonexistent implementation. The scoped capability issue must precede implementation. No event, source owner, mapping row, role or export is approved here.

1. **Separate original science, actual bridge and root selection.** Consume the unchanged W07 conditional decision JSON, its actual native review pair, per-target assessments, peer science/skeptical reports and source/input pins. Verify that each of its four target selectors identifies the corresponding decision and that the reviewed whole-owner and field payloads actually match. Read reviewer identity/independence basis and authorship provenance, with root checking the real assignment; `independent:true` or a matching schema/hash alone cannot establish independence. The original decision remains CONDITIONAL/WITHHOLD. A separate exact actual-generation bridge and root-selected publication plan determine readiness to execute the bounded policy transition. They do not change the original decision or admit a mapping. The current publisher has no separate acceptance document, and its approval is NONE: document the actual new validation boundary and external root selection without claiming an existing field already performs acceptance.

2. **Keep the temporal/hash graph acyclic.** Freeze source acceptance before source application. The actual source receipt/generation and the suppression bridge can only be bound afterward; never rewrite the already consumed owner plan or accepted review list to include future artifact hashes. The publication plan can reference the completed actual-transition review. Policy history may hash the plan, decision, source receipt and native mapping receipt (canonical endpoints). It must not hash the final publication success log, which itself contains the policy hash. Any final exact-plan review belongs outside the plan it hashes. The native mapping receipt stays approval-free and does not itself authorize sidecar science.

3. **Use typed, exact event and field joins.** Require integer (not bool/float) version, duplicate-key refusal, closed fields and safe regular relative file references. The sealed four-pair decision is the scope, not a free allow flag. Recompute selected new requirements from the actual native generation and require exact set equality to the reviewed set; reject duplicates, missing/extra keys and changed credits. Compare all eight event columns. When bridging diagnostic roots to actual generation, the seven columns other than `source_refs` must remain exactly native/evidence-equal; for source refs bind each original ref and actual ref separately to a verified root, authentic repository-relative owner path, exact owner bytes and exact field locator/literal. Reproduce the native actual ref rather than rewriting the old string. All original diagnostic refs and manifests stay intact. A substantive field/owner/credit change requires a fresh scoped review; path relocation alone does not imply new science or actual approval.

4. **Model genuine owner roles.** There are eight proposed owners, seven real preimages, six selected source operations and two unchanged credited owners. Bluensomycin and Congocidin have authentic unchanged baseline owners: verify before/after inventory equality and their baseline captures without inventing operation/case joins. Corn_Starch has the one genuine create/null preimage. Other source operation/case joins must match the actual completed source proof and original proposal provenance. Recompute the complete preferred-name credit set over the full actual mapped inventory, not only these eight files. Preserve legitimate multiple credits, literal/native order and every credited-owner hash; no winner selection or credit trimming.

5. **Append exact native physical lines.** Validate the old header/row structure and immutable preimage; keep its entire 34-row byte prefix and row order. Append only the four actual native lines in declared deterministic order, preserving all eight cells and native JSON string serialization. Require exact expected after hash, no duplicate header/key or silent sorting. Keep the baseline bytes unchanged. The 21-event diagnostic is evidence, not a replacement sidecar. Historical shared events may have old source paths; do not rewrite those paths/credits or treat the different old/current provenance as permission to replace them. Under this initial contract an attempted old-pair credit change is refused. A missing final newline or incompatible native header is a refusal, not permission to repair historical bytes silently.

6. **Enforce both native validators and stronger reviewed-context checks.** Unchanged Claw `_validate_pair` verifies pair structure and token absence but, by design, accepts missing expected events and nonempty wrong credits. Actual source/owner/event comparisons must add those missing contextual guarantees. The suppressed token must be absent on every projected subject row, including all registry siblings. Keep whole-catalog Rule K and the existing baseline strict; no expanded exceptions and no unrelated-row edits. Compare all old native sidecar keys before projecting into dictionaries so duplicate old evidence cannot disappear. Whole-output/global impacts remain separately gated even though only four new selected sidecar events are authorized.

7. **Make sidecar a real third transaction destination.** In the current publisher, explicit integration points are `prepare`'s before/actual checks, closed review/generation refs and role separation; `_policy`'s artifact endpoint/update; the returned prepared snapshot; `publish`'s destinations/current captures, backups and reserved handles; `recheck`'s current-state exclusions and exact backup/content reads; summary/log fields; and completed `validate` reconstruction. Reserve sidecar-before.tsv along with the existing backups/native receipt/log before any mutation. Read back all three destinations and backups after each write and at completion; verify the source proof, actual producers, review files, inventories, historical receipt membership, unchanged baseline and live accepted HEAD at the last bounded observation. A partial failure must preserve recovery and clear success-shaped native/publication receipt bytes. Do not create a fourth unguarded write path or weaken the current source/index/HEAD contract.

8. **Historical validation remains replay, not perpetual live locks.** Reconstruct expected sidecar append from immutable beforeimage, actual generation, complete reviewed event/credit evidence and the precise publication plan. Require actual canonical/policy/sidecar equality, immutable baseline and 27-prefix plus one genuine successor. Source `verify_completed` already reconstructs protected history from its reserved copies; do not weaken it or add a forever-current-HEAD constraint. Legitimate later commits remain allowed. Recovery backup integrity is enforced through live success; a standalone historical verifier checks recovery files only if that separate contract explicitly binds them. The existing publication `validate` expects this publication to be the latest receipt; do not accidentally claim arbitrary later publication-chain suffixes are supported.

Required tests include real source→pinned generator→publisher transition, exact 34→38 suffix, complete prior27/owner-attribution/baseline preservation, root/field/credit bridge negatives, true multi-credit positive, malformed version/duplicate keys, alias roles and late substitution, partial-write recovery, completion-boundary drift, later-commit replay, v1 unchanged refusal, and retention of every old assertion. Test the unchanged-but-credited and genuine-null-owner roles explicitly. No schema-only or fabricated accepted review fixture can substitute for actual-boundary integration tests.

All unresolved Congocidin PLACEHOLDER/UNKNOWN_TERM, original Bacto scope, source quantities/forms/roles and the 20-owner/51-claim companion envelope remain. One of the four events removes an old canonical token; the other three record new native suppression requirements. Counts of events are not counts of changed canonical cells or scientific resolutions.
