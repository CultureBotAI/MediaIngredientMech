# Closed suppression publication transport

This is the implementation interface under #1259, not a frozen implementation or an application approval. The verdict-consumption finding is preserved and its repair was authorized by issue comment 6721929601. Native passing verdicts and passed required checks are required; original conditional scientific limits remain intact.

Existing publication v1 is unchanged. Publication v2 uses every v1 key, changes `schema_version` to integer 2 and `kind` to `unmatched_campaign_publication_v2`, and adds exactly `suppression_review: {path, sha256}`. All references are canonical repository-relative paths and lowercase SHA256 digests.

The suppression review selection JSON has exactly these keys: `schema_version` (integer 1), `operation` (`select_campaign_suppression_transition`), `issue` (`https://github.com/CultureBotAI/MediaIngredientMech/issues/1259`), `selected_by` (`/root`), nonempty `selection_basis`, `original_review`, `transition`, and `transition_review`.

Each review bundle is `{yaml: {path, sha256}, markdown: {path, sha256}, inputs: {DECLARED_NATIVE_INPUT_PATH: {path, sha256}, ...}}`. The inputs map must cover every declared native review input exactly. Captures retain declared historical paths in the mapping, rather than rewriting the original review. Original W07 YAML and decision are pinned by the implementation. The actual transition review is separately authored and root-selected after the real source receipt and generation exist; no future hash is inserted into the already-consumed source plan or acceptance.

`transition` is `{path, sha256}` referring to the exact technical transition returned by `derive_suppression_transition(capture, plan, before, owner_proof, diagnostic_sidecar, projected_canonical, needs, original_review)`. That function is an evidence constructor, not an acceptance gate. It returns `(sidecar_bytes, transition_object, original_review_document)`. Its object has exactly `schema_version`, `operation`, `issue`, `original_decision_sha256`, `owner_plan`, `owner_receipt`, `generation`, `publication_producers`, `before`, `receipt_prefix`, `native_context`, `mapped_inventory`, `events`, `after_sha256`, and `approval: NONE`. Exact key values and event joins are rederived by prepare/validate; adapters must not invent them.

The existing `prepare(root, plan_path, completed=False)`, `publish(...)` and `validate(...)` interfaces remain. Live v2 prepare requires the selected original review, exact actual-transition review and root selection; it does not synthesize acceptance. The four events append to the exact 34-row historical sidecar. Two credited owners remain unchanged roles without fabricated operations. The native mapping receipt remains the policy entry's receipt dependency; the success log is not hashed into policy.

An adapter successor may transport the selected review reference and call the existing prepare API. It must preserve its v1 behavior, require explicit v2 selection, and refuse absent review/bridge artifacts. The real six-owner integration fixture is still under validation, so neither this interface note nor its helper is a claim that the campaign is ready to publish.

Issue comment 6721966895 authorizes a narrow sequential-checkpoint refinement: the complete actual receipt prefix may include an already-completed native suffix after the original 27 exact path/hash pairs. Native contiguous full-chain replay, source checkpoint/protected captures and current endpoints remain mandatory; the entire prefix is included in the independently reviewed transition. This does not permit a fabricated future suffix, skipped links, altered originals, sidecar/baseline drift, or changes to the eight reviewed owner roles. A separate actual-transition artifact is required, but the originally independent scientific reviewer may author it if its current assignment remains independent of the relevant authors. Reviewer metadata is not a substitute for that externally audited assignment.
