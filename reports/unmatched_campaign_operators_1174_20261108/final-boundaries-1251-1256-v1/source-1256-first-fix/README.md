# #1256: live Git baseline and tracked-scope freshness

This is a separate private successor to the sealed #1255 patch. Its two preimages were verified against actual commit `7a990e36b0e08d1deff943fe58bdc40d24d3834f`; the earlier 16c archive and #1255 packet remain unchanged. Root filed #1256 before authoring. The independent W08 counterexamples and C's separate transaction/historical-contract assessment are hash-bound under `independent-inputs/`. No I, J, K, maintained owner, worker, GitHub or session was changed by this author.

`_check_mutation_git_state` checks the current HEAD against the accepted `baseline_commit`, lists literal NUL-delimited tracked changes relative to that fixed commit, compares the unchanged complete set of allowed source/destination paths, and checks HEAD again. Existing `_recheck` invokes it after the existing producer, input, owner inventory and receipt-prefix checks. Final application also invokes it before completion. Existing prewrite, postwrite/retirement and both `finish_receipt` callbacks therefore enforce live freshness without relying on a movable diff base.

This covers two different errors: a late commit cannot change the accepted transaction baseline, and unrelated tracked/staged drift cannot wait until after owner mutation to be detected. Preexisting drift fails before receipt reservation or source writes. Drift injected after a write or during final success publication retains an honest failed/recovery-required receipt and backups. No rollback is claimed. Planned owner transitions are still allowed only through all existing before/after/history/inode/provenance guards; the allowed-path set itself has not widened.

`verify_completed` is byte/AST unchanged. It remains a historical content verifier: after a genuinely completed transaction, later commits may occur while the exact reviewed owner endpoint, consumed code/evidence and recovery/checkpoint proofs remain valid. Current owner or receipt tampering still refuses. A historical success does not authorize a new source transaction or a new publisher transaction. The separately assigned publisher #1256 work is outside this patch; this packet does not claim to fix its live lifecycle.

The original 16c 80,127-byte test prefix and all its assertions are unchanged. The #1255 Unicode/control-character positive test is unchanged. Two #1255 negative harnesses now assert the stronger prewrite refusal, unchanged owners and no receipt directory rather than a postwrite recovery receipt; their malformed path and unrelated file cases are retained. The malformed-listing hook follows the fixed accepted-baseline argument. These are direct consequences of the scoped #1256 behavior, not weakened checks.

Eighty-one new parameterized cases cover edit, create, promote and demote: early and late empty/unrelated commits; dry-run freshness; commits before/after writes and after the final receipt flush; unrelated staged changes before apply, before/after writes and at final flush; valid historical replay after later commits; current-owner and receipt tampering; and an actual Git argv check proving the fixed baseline with literal path output. Fault injections execute real private Git commits/staging and call the original native functions; they do not fake a HEAD or return a fabricated completed proof.

`draft-head-only-v1/` and its 60-passed first run are preserved. That initial draft checked HEAD and the final diff only; before completion root clarified the already-filed scope also requires early and repeated unrelated tracked-scope checks. The final source and 104 focused passing cases (81 new plus 23 #1255) implement that complete source-side scope. No partial draft is offered as final. Final full regression counts and exact hashes are recorded only in HANDOFF after completion.

`patch-v1.diff` is relative to exact 7a preimages and passed `git apply --check` privately. The source operator and its focused tests are the only proposed maintained paths. Ruff, Black and Mypy were checked in the existing Python 3.13 environment without installation. Final root commit, full native checks and distinct exact-head review remain required; no scientific, mapping, role, whole-campaign or export approval follows from this technical correction.
